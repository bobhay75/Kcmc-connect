# KCMC follow-up scoped hosting repair

This package updates exactly six existing code files for the device-notification test and clearer links:
`sw.js`, `member/push-settings.js`, `member/notifications.php`, `admin/push.php`, `index.php`, and `admin/operations.php`.
It is intended for the already installed theme/navigation, manual time clock and health actions release.

The complete six-file tuple must match either the reviewed before image or the final after image. The main and installed
livecalendar homepage variants are independently pinned. The livecalendar variant retains its historical photo class
ordering, and receives only the same uniquely anchored homepage edits reviewed in canonical source. Unknown code,
partial before/after bundles, unsafe ownership/modes, changed read-only prerequisites and unfinished journals in either
public variant are refused. No force, reset, stash, chmod, full deployment, source fetch or repository update is used.

The existing-file mover and corrected dependency extension are byte-for-byte copies of the previously reviewed engine.
The browser script depends on the worker, both install before the notification page, and the administrator guide depends on that page.
Recovery retains all transitive providers if a consumer replacement has an uncertain outcome. Backups and journals
remain outside public_html with private permissions; existing code mode 0644 or 0664 is preserved. A real PHP8.2 CLI
performs version and staged PHP syntax checks before any replacement; no application PHP is executed. Browser script
syntax and behavior are checked in the source CI, rather than requiring Node on the hosting account.

The installer does not read or change configuration, VAPID keys, subscriptions, content, accounts, roles, time records,
payroll settings, delivery configuration, mail, cron or the hosting repository. It does not send notifications or email.
The owner must use the installed device-test screen to request a local Windows notification, and the existing self-test
control to request an actual push send when ready.

## Derivation and acceptance

The exact BASE_COMMIT and SOURCE_COMMIT in derive_installer.py anchor the runtime review. The capture script records
only those six app deltas and unchanged actual code dependencies. Exact evidence bytes, manifests, wrapper, transaction
engine and extension are checksum pinned. `python3 -B derive_installer.py` must reproduce installer.py and provenance.json.
The host workflow runs source-object provenance, isolated transaction cases, the existing 72 transaction/policy checks,
actual Python3.6 and real PHP8.2 staged apply/no-op/rollback for both public variants and both supported code modes.

## Hosting use

Download the final installer from its immutable reviewed commit, verify its published SHA256, then run:

```sh
python3 -I -B installer.py check
python3 -I -B installer.py apply
python3 -I -B installer.py check
```

A successful final check prints `CHECK ALREADY_REPAIRED` and all six final hashes. Repeating apply is a no-op without a
new backup. `diagnose` reports fixed code hashes/metadata only. To roll back, retain this exact pinned installer and use
its printed `rollback --session repair-...` command. Do not rerun superseded theme/manual/health installers after this
update; their older prerequisite guards correctly refuse the newly reviewed code.
