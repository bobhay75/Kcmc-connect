# KCMC October 13 scoped release

This helper installs exactly ten application files from reviewed runtime commit [4225fce8968747ad4f828a9a36087b04fd020484](https://github.com/bobhay75/Kcmc-connect/commit/4225fce8968747ad4f828a9a36087b04fd020484): Publication Designer, bootstrap, the retouched building JPG, the Trunk or Treat SVG, the repaired 512-pixel PNG icon, the web manifest, the homepage, public stylesheet, public JavaScript and service worker. It accepts one complete baseline, `268bebca444bd4970bb4ecaa0d6eceb6a11988fd`: eight existing files with exact approved hashes, sizes and modes, and both new image files absent. Mixed, incomplete or unknown file states refuse before downloads. An already complete target takes the verified no-op path described below. Repository HEAD alone does not establish the live application bytes; preflight checks them separately.

Close Publisher tabs and let pending saves and uploads finish before apply or rollback. Keep Publisher idle until the command finishes. Its locks cannot drain PHP requests that started earlier. Confirm web PHP and the command use the same `KCMC_PRIVATE_DATA_DIR`, or the existing default `data/private` directory. The CLI guard does not prove an externally configured PHP-FPM storage path.

Use the separately supplied immutable, checksum-verified launcher. Standalone entry points are `python3 installer.py preflight`, `python3 installer.py apply`, and `python3 installer.py rollback --session BACKUP_DIRECTORY`. Save the printed protected session directory. All affected-file backups and the precautionary `data/content.json` copy stay outside `public_html`.

The installer verifies staged immutable bytes, PHP 8.2 syntax and JavaScript syntax when Node is available. It validates staged SVG XML and MIME without PHP DOM or getimagesize on SVG, and checks raster MIME/dimensions with PHP getimagesize and fileinfo; the 512-pixel icon must be 512×512. Baseline images are hash-checked only, so a known malformed baseline icon does not block its repair. It installs bootstrap before PHP consumers, artwork/icons and the manifest before their consumers, and the service worker last. Read-only HTTP checks verify the new homepage photo and `blue-fish-menu-20261009` asset URLs, exact public static bytes (including SVG, icon and manifest query URLs), the trunk-art-20261011 worker, staff sign-in and protected Publisher redirects. Designer's Undo/Redo code is pinned as source; authenticated editing and printing remain separate staff acceptance.

Fourteen unchanged files are guarded, including the original building artwork, the existing Publisher projects/media endpoints, staff dashboard, readability pages and authentication entry. Existing ownership and modes are preserved. Targets cannot be symlinks or hardlinks. No files are deleted on apply.

Failure attempts an affected-code rollback. Manual rollback checks the saved installation lease and refuses later file or Publisher-store changes before restoration. It restores only the affected code/assets and removes either new image only when it is still this installation's verified file. Private publication/media JSON is fingerprinted under application-compatible locks without copying, printing, replacing or restoring it. The two coordination lock files may be created. Live editorial content is checked and privately backed up but never replaced or restored. Configuration, accounts, prayer, timecards and other private records are outside the replacement scope.

When all ten targets already match, apply checks their modes/owners, captures existing protected-file and Publisher-store fingerprints, verifies anonymous HTTP responses, and rechecks all leases. It then reports "Pinned runtime already present; read-only checks verified; no application file replaced." No stage download, backup session, JSON backup copy or rollback occurs on this path. Coordination locks may still be created. A failed current-runtime check refuses without attempting a downgrade.

The installer performs no Git operations, broad sync, content insertion or repository alignment. The separate `align-repository.py check` and `align-repository.py align` entry points verify the exact clean `268bebca` main checkout before fetching and fast-forwarding to the pinned reviewed `4225fce8` release. If the checkout already equals that exact target, it must pass the same clean-tree checks and reports verified without fetching or updating. Every other revision and all tracked, staged, untracked or ignored edits refuse. Hooks and autostash are disabled; no configuration or application deployment is invoked. A failure after an update attempt explicitly requests HEAD/worktree review instead of claiming that nothing changed. PR #117 is outside this release; it must not be merged or deployed by this helper. Align the existing host repository separately only after confirming its checkout is clean. Do not use cPanel Deploy HEAD while it could overwrite the scoped release with older code.

CI should run `verify-inventory.py` with both immutable source commits fetched, run the temporary-directory transaction fixtures on Python 3.6 and current Python, and lint the pinned runtime PHP/JavaScript. Local fixtures do not establish signed-in staff workflows or real-device update, offline and Web Push acceptance.
