# KCMC scoped host repair

This October 8 repair installs reviewed runtime `f4442fc4cce2121828544b79b8ba3591c5fe0dab`, approved by [PR #108](https://github.com/bobhay75/Kcmc-connect/pull/108). Its replacement scope is 16 application files: six code files, the Publisher media endpoint, and nine supplied images. It accepts exactly one complete preimage bundle: `ae004a659a7c2fb334296fa41f54dd5263f4d5c0` (six existing files and ten absent files), or the installed `61c70f590735522adbfd6be02dab6888924a54fd` release (all 16 files). Mixed, incomplete, or newer states refuse before source downloads. The independent baseline inventory records both complete bundles; the release inventory records source hashes and 13 preserved guards.

Before applying or rolling back, close Publisher tabs and let all saves/uploads finish. Keep Publisher idle until the command completes. Its coordination locks cannot drain PHP requests that started earlier. Web PHP and this command must use the same `KCMC_PRIVATE_DATA_DIR`; the approved bootstrap uses that environment variable or the default existing `data/private` directory. A CLI/default path check does not establish an externally configured PHP-FPM environment.

The installer checks preimages and guarded files, records the selected allowlisted baseline in its private journal, stages and hashes each immutable download, runs PHP 8.2 syntax/image checks, makes private backups outside the web root, and replaces dependencies before consumers, with the service worker last. Anonymous HTTP checks verify the public pages, protected Publisher routes, and exact static bytes. Failure attempts a scoped code rollback to that selected original bundle, preserving each original file's presence and metadata. Rollback refuses newer code or Publisher-store edits. Private publication/media JSON is fingerprinted under its two application locks but is never copied, printed, restored, or replaced. The two coordination lock files may be created.

`data/content.json` is backed up privately and checked for concurrent edits, but is never replaced or restored. Accounts, prayer, timecards, configuration, and other private stores are outside the replacement scope. The helper performs no Git operations or broad deployment sync.

Run the SHA-256-verified, commit-pinned launcher supplied with the release. The standalone entry points are `python3 installer.py preflight`, `python3 installer.py apply`, and `python3 installer.py rollback --session BACKUP_DIRECTORY`. Save the backup directory printed by the installer. Before a later rollback after staff use, establish the web runtime's actual storage selection; the CLI/default guard alone cannot prove a hidden PHP-FPM override. Keep Publisher closed and drained during any rollback.

The scoped installation does not advance the host repository. Repository alignment is a separate step after successful installation. Keep cPanel **Deploy HEAD** out of this repair: `.cpanel.yml` uses a broad `rsync --delete`, which the scoped installer does not invoke.

`align-repository.py check` inspects the fixed host checkout without updating it; `align-repository.py align` is a separate repository-only operation after the scoped installation succeeds. It requires the original `ae004` main checkout, Git 2.32+, ordinary files, and no tracked, staged, untracked or ignored edits. It fetches the pinned reviewed runtime over credential-free public HTTPS and performs only a fast-forward, with hooks, conversion filters and autostash disabled. It never invokes cPanel deployment, discards edits, edits configuration, or pushes. A failure after the checkout update starts explicitly asks for HEAD/worktree review and does not try to undo local changes.

`content-review.py` is a separate read-only comparison of the approved October 13 Hope Keepers event with the unfiltered host content. It reports hashes and a conservative verdict without printing other host records or changing content. It refuses an expired candidate.

`insert-hope-keepers.py --apply` is the separately reviewed one-event content repair. The owner's October 8 unfiltered comparison established that the candidate is missing without a possible duplicate. This helper requires that exact host SHA-256, refuses any newer content or expired candidate, appends only the approved candidate bytes to the existing top-level events array, and preserves all original bytes and metadata. It saves an exact private backup outside the web root and atomically replaces the file with its existing ownership/mode. Keep Publishing Desk tabs closed with publishes finished through the post-install public check. Its lock cannot drain older PHP requests. It never restores content automatically; interruption after commit is reported distinctly.

The fixtures cover interrupted replacements and journals, resumed rollback, permission/inode changes, symlinks, hardlinks, Publisher-store drift, locks, immutable downloads, lint discovery, and anonymous HTTP checks. CI verifies the independent source inventory and runs the fixtures on both current Python and Python 3.6. Signed-in staff workflows and physical-device offline/update/push acceptance remain separate checks.
